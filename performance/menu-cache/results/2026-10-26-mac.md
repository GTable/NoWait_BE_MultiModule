# Mac 측정 원본 (2026-10-26 21:51 ~ 22:13)

EC2 가 꺼져 있어 먼저 잰 측정이다. 앱·k6·도커가 한 기계(Apple Silicon 8코어, 16GB)의 CPU 를 나눠 쓰므로 절대값보다 단계 간 차이를 본다.

실행 조건
- `LOCAL=1 performance/menu-cache/run.sh ...`. MySQL 8.0.36·Redis 7.2-alpine 은 도커(Docker Desktop, 각 `--cpus=1 -m 1g`), user-api·admin-api(JDK 17)와 k6 는 Mac 에서
- 데이터·트래픽·예열·측정 시간은 EC2 와 같다(주점 200, 목록 조회만, 품절 토글 초당 1건, 예열 100 req/s 20초, 속도마다 60초 1회)
- 2단계·3단계는 200·500·1000 을 먼저 재고, 한계에 닿지 않아 2000·3000 을 따로 다시 쟀다(사이에 앱을 다시 띄웠다)

## EC2 와 다른 점

- 순서와 한계의 자리는 EC2 와 같았다(N+1 < JOIN < 인덱스 < 캐시). 숫자는 EC2 가 더 좋았다: 같은 단계·같은 속도에서 p95 가 더 낮고, N+1 의 처리 상한이 116~146 → 187
- Mac 은 앱·k6 가 MySQL 과 같은 기계에서 돌아, p99 가 들쭉날쭉했다(예: 인덱스 1000 req/s 의 p99 42.8ms)
